# Demo 视频脚本

目标：**2~3 分钟**讲清楚系统能做什么。重点不是讲技术，而是让观众看到
**上传 → 提问 → 引用 → 多轮对话 → 删除**这条完整闭环。

---

## 一、录制前准备

```bash
# 1. 清空历史数据，保证录屏时是干净状态
docker compose down -v
docker compose up -d --build

# 2. 确认后端和模型都就绪（第一次会触发模型下载，务必提前预热）
curl http://localhost:8000/health

# 3. 准备一份内容明确、有标题层级的测试文档（推荐 Markdown，切分效果好）
#    上传前先删掉 documents/ 里的旧文件，避免"文件已存在"的分支
```

打开 http://localhost:8501，浏览器按 `F11` 全屏，缩放调到 110%~125%，关掉无关书签栏。

> 💡 提前把 `curl http://localhost:8000/health` 跑一遍很关键：它会触发 BGE 权重下载（约 95 MB）。
> 否则录到"提问"那一步会卡住十几秒，很难看。

## 二、分镜脚本

| # | 时间 | 画面操作 | 旁白 / 字幕 | 要展示的重点 |
|---|---|---|---|---|
| 1 | 0:00–0:15 | 展示整体界面：左侧文档管理，右侧聊天区 | "这是一个基于 RAG 的知识库问答系统，上传文档就能用自然语言提问，回答会带上出处。" | 一句话说清产品定位 |
| 2 | 0:15–0:40 | 点侧边栏「上传文档」，选一个 PDF/MD，点**确认上传** | "先上传一份文档，系统会自动解析、切分、向量化并入库。" | 上传按钮**始终可见**（选中文件后才可点） |
| 3 | 0:40–0:50 | 展示「已入库文档」列表刷新出文件名和 chunk 数 | "入库完成后，文档会出现在已入库列表里。" | 入库结果可见、可核对 |
| 4 | 0:50–1:20 | 在输入框提一个文档里明确写了答案的问题 | "现在问一个只有这份文档才知道的问题。" | 检索 + 生成 |
| 5 | 1:20–1:45 | 等待回答出现，**展开「📖 查看引用来源」**，逐条点开展示原文 | "注意回答里的 `[1]` `[2]` 标记，展开引用可以看到命中的原文片段、文件名、页码和相似度分数。" | **这是本项目的核心卖点，务必留足时间** |
| 6 | 1:45–2:15 | 紧接着提一个**依赖上文**的追问（例如"那它有什么缺点？"） | "它支持多轮对话——追问会自动结合上下文重新理解，不需要把问题重复说一遍。" | 多轮改写生效，能答出指代 |
| 7 | 2:15–2:30 | 点文档右侧的 🗑 删除，展示列表变空 | "不需要的文档可以直接删除，向量和原文件会一起清掉。" | 删除闭环 |
| 8 | 2:30–2:45 | 切到 http://localhost:8000/docs | "后端是 FastAPI，所有能力都开放成了 REST 接口，Swagger 里可以直接试。" | 工程完整度 |

**总时长控制在 2 分 45 秒以内。**

## 三、录制建议

- **工具**：Windows 用 `Win + G`（Xbox Game Bar）或 OBS；只要录浏览器窗口，不要录整个桌面
- **鼠标**：点击前稍作停顿，别让观众追着光标跑
- **语速**：宁可语速慢一点、句子短一点；旁白最好录两遍取一遍
- **字幕**：后期加中文字幕，GitHub 上大部分人静音看
- **加速**：等待回答的部分可以 2 倍速，但**第 5 步（展开引用）不要加速**，那是重点
- **导出一份 GIF 或 15 秒片段**放进 README（控制在 5 MB 以内），完整视频传到 B 站 / YouTube 后在 README 顶部放链接

## 四、录制时容易翻车的点

| 坑 | 规避方式 |
|---|---|
| 第一次提问卡十几秒 | 提前 `curl /health` 预热模型 |
| 上传后提示"文件已存在，已重新入库" | 录制前清空 `documents/` 或换一份新文档 |
| 「已入库文档」是空的 | 先确认 `/documents/list` 有数据；数据卷被重建过就点「🔄 重建索引」 |
| 回答是"根据现有资料无法回答" | 问题要能从文档里找到答案；核对 Top-K 是否命中 |
| 删除时提示 404 | 列表没刷新，先刷新页面再删 |
| API Key 泄露在画面里 | 不要录终端里的 `.env`，录制前关掉含 Key 的窗口 |
